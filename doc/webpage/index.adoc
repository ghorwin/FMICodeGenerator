== What is this FMI/FMU stuff?

FMU stands for _Functional Mockup Unit_ and FMI for _Functional Mockup Interface_. The latter is an industry standard for simulation model runtime coupling, and basically defines an API and a meta data description file and directory structure: see the {fmi-url}[FMI-Standard webpage] for details.

== Why a code generator?

When you want an *efficient/fast* FMU slave, there's probably no way around a native C/C++ implementation. However, implementing the C interface functions, the data handling, input/output variable handling and advanced features like *saving and restoring the FMU state* is not so simple and straight-forward.

The process of setting up the FMU (core files, `modelDescription.xml`, directory structure) is pretty similar for most projects and can be automated with a configurable code generator — hence this project.

== Features

image::VariableDefinition.png[width=800px]
image::GenerationSucccess.png[width=800px]

* Graphical wizard (Python/Qt 6) and command line generator
* Generates FMI 2.0 FMUs for _Model Exchange_ and _Co-Simulation_
* Generates `modelDescription.xml`, value reference defines and variable handling
* Generic FMU state serialization (get/set/serialize FMU state) — you only add your model-specific state
* Re-run the generator to change variables: generated files are updated, *your own code stays untouched*
* CMake and qmake (Qt Creator) build files, build and deploy scripts for Linux, macOS and Windows
* Small, readable code **without third-party library dependencies**

== What FMI Code Generator _is not_

This is not a Software Development Library/Toolkit for accessing/supporting the FMI interface. Look at the https://github.com/qtronic/fmusdk[FMU SDK] or other projects on https://github.com/fmi-tools/[fmi-tools] if you need something like that.

Actually, the code generated by *FMI Code Generator* hides most of the messy FMI C function interface (including most of the memory management related to instantiating/deleting slave instances, and the state storage stuff) from the typical (engineering) user.
